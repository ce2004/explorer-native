# Apple Music

Part of the Explorer Native notes for Claude; CLAUDE.md says when to read this file.

## Apple Music

Browsing is ours; playing is Apple's. Legitimate: no DRM is broken. An earlier attempt decrypted the streams with a Widevine device key (Widevine.cs, Mp4Cenc.cs) and was dropped; never bring it back.

- `AppleMusicClient` (src\AppleMusicClient.cs) is the amp-api web client, signed in with the `media-user-token` cookie from a cookies.txt (what gamdl reads), through `GoogleNet.Handler` like everything online. The developer token is scraped from the web player's index.js, as gamdl does. `ListAllAsync` pages big library lists 8 at a time off the first page's `meta.total`. `StartAsync` is gated and cached. Every failure is an `AppleMusicException` with a sentence; `SignIn` true means "set it up again in Preferences".
- `AppleMusic` (src\AppleMusic.cs) is the place in the panes. Paths are under `"::applemusic"`; song paths have NO extension (4.0.0 gave them `.m4a`, and the file player took them for files: "Cannot play Apathy.m4a, opening it instead"). `Is`/`DisplayPath`/`SearchPath`/`FromTyped` (Ctrl+L). Items and per-folder listings are held in memory for the session; F5 calls `Forget`. A list shown from memory is re-asked of Apple behind it (`CanRefresh`: library lists, albums, playlists, artists, recently played, at most every 30s; never the fixed menus, a search or a station) and swapped in silently with `ReplaceEntriesInPlace` (`RefreshAppleMusicQuietlyAsync`): Conner wants changes noticed but NVDA not told.
- Every MainForm path that touches the disk, the shell, the clipboard or the file player must check `AppleMusic.Is` as well as `Archive`. 4.0.0 shipped with Enter, the 4s availability probe (sent you back to the drives), F5, F1, the watcher, prefetch, details, Properties, Copy, Copy path, the Windows menu, folder size, Song properties, Ctrl+L, the title and LastFolder all missing it. `RefuseForAppleMusic` is the refusal for file-only commands; `ShowArchiveHidden` and the context menu's `inArchive` cover Apple Music. AppleMusicTests.Wiring checks the key ones in MainForm's source. Folders: top (Search, Library, Recently played, Stations), Library (Recently added, Playlists, Albums, Artists, Songs), an album/playlist/artist/station's children, and a search's results split by kind. Library songs and albums are fetched `sort=-dateAdded` because a song carries no date of its own — that order is the only `AddedRank` there is.
- Sorting is Apple's own set, not the file columns (`Sort` enum, `SortsFor` from what the folder holds, `Ordered`, `DefaultSort`, `StartsAscending`). `Ordered` records the shown order in `Displayed`, which is what `NextSongAfter`/`PreviousSongBefore` (play-on) walk. Stored in `Settings.FolderSorts` with an `apple:` prefix (`AppleSortFor`/`SetAppleSort` in MainForm), so it never collides with a file folder's `SortColumn`. The Sort submenu is rebuilt per open (`PopulateAppleSortMenu`), and is called "Sort by" there; the File menu hides it when the list offers nothing (a submenu whose only item is disabled traps NVDA). The submenu must have items from construction (`BuildSortMenu` adds the file items up front): a ToolStripMenuItem with none has no arrow, is clicked instead of opened, and never raises DropDownOpening.
- MainForm: a `"::applemusic"` row is appended in `LoadDrivesInto` when `IsSetUp`; `NavigateAsync` branches to `ShowAppleMusicFolderAsync` before any disk probe; `SafePathRoot` sends "up" back to the row; `RealFolderOf`/`RealFocusOf` save the drives view with the cursor on the Apple Music row as LastFolder. `ActivateFocused` sends any Apple row to `OpenAppleMusicRow` first (folder: open; Search: ask; song: `Program.PlayAppleMusic`). Entries have Size -1 so nothing says "0 bytes".
- `AppleMusicPlayer` (src\AppleMusicPlayer.cs) plays through Apple's MusicKit JS v3 in a hidden off-screen WebView2 (the one package exception beyond the audio codecs; the Edge runtime ships with Windows 11). The page (`PlayerHtml`) loads only musickit.js (no web-component UI), is configured with the developer token and seeded with the `media-user-token` (same value as MusicKit's music user token, so no second sign-in), and relays play/pause/stop/seek/volume and reports state back over `postMessage`. Hotkeys route to it from `RunAudioActionCore` whenever `AppleMusicPlayer.IsActive`; speed/pitch/EQ/silence say "not available for Apple Music" because the sound is sealed. Starting a song stops the built-in player and the reverse. Play-on and end-of-list, and a station's "give me more", are in the player. Every play has a generation number: only the newest may report an error or an end, the page posts "ended" once per play (MusicKit says 5 then 10 for one song) and never while switching, so fast Enter presses neither fail nor skip. Seek counts from the last target for 1.5s (the page's clock lags a seek) and says where it lands. Volume is the app's `AudioVolumePercent` (capped at 100) and changes made while Apple plays are saved to it; mute restores the previous level. `AudioState` reports Apple's player while it `IsActive`. The environment is created with `--autoplay-policy=no-user-gesture-required` (nobody clicks the page). Start-up has a 25s timeout and a failed start is torn down (`Reset`) so the next play retries. `EXPLORERNATIVE_APPLEMUSICLOG=<file>` logs the page's reports (never tokens). Next/Previous track (4.1.2, Conner) are shortcut-only actions with no default key (every letter of "Previous track" is already an Audio menu access key): Apple Music goes through `NextFor`/`ListPlace` (`SkipToNext`/`SkipToPrevious`), files through the track folder's audio files in the order a pane shows them (`MainForm.AudioFilesShown`) or by `NameRules.CompareNames` read off the UI thread. New actions go at the END of the enum (hotkey ids are 0xB100 + value). Enter on a station plays it (`PlayAppleStation`, fresh tracks, cursor stays). Verified live in Chrome against the real account: setQueue{song}, play, seekToTime, pause/resume, volume, stop; `playbackState` 2 playing / 3 paused / 4 stopped / 5 ended / 10 completed; auto-advance on 5 or 10; event is `nowPlayingItemDidChange`. GUI/audio were not run here — that needs the real app.
- 4.0.2 (Conner: slow to start, too much CPU, skipping lags, device ignored), all measured live:
  - Speed: `Warm()` from `ShowAppleMusicFolderAsync` starts the page while browsing (closed by `CloseWhenIdle` after 5 min with nothing loaded); the page preconnects Apple's hosts and opens the Widevine CDM early. Songs go in as whole queue items (`item(id)`, `library-songs` for `i.` ids), skipping MusicKit's 0.4s catalogue lookup (falls back to `{song}`). The next song in the list is queued too (`next`/`append`, MusicKit `playLater`), and the page posts `advanced` when MusicKit moves on (`OnAdvanced`): ~0.25s between songs instead of 0.5-2.4s. MusicKit says state 5 BEFORE it moves to a queued item, so "ended" waits 2.5s (`advances` counter) whenever something is queued. First play in a warm page ~1.8s (was 3-6s), later ones ~0.5s.
  - Skips: inside `audio.buffered` the page sets `audio.currentTime` (2-10ms; MusicKit's clock follows), otherwise one `seekToTime` at a time with the newest target (each took ~270ms and a held key queued dozens). C# sends one seek at a time (`_seekQueued`).
  - CPU: state is posted only when the state or the whole second changes (was ~4/s). Paused, the page uses 0%.
  - Device: `SetOutputDevice(windows name)`; the page matches `enumerateDevices` labels (same as WasapiRenderer's names) and calls `setSinkId`. Needs the Microphone permission (`Profile.SetPermissionStateAsync` for https://music.apple.com); the page's getUserMedia is removed and every PermissionRequested is denied. The Output device dialog is no longer refused while Apple plays; arrowing moves both players. Verified with one endpoint here (sinkId set, peak 0.1); this PC has no second output to prove a move.
  - Reliability: `ProcessFailed` restarts the song where it was (third crash in a minute gives up with a sentence); `WatchStart` restarts a song with no sound after 15s once. Killing the renderer live: back in 3.5s at the same second.
  - Rows read artist first ("Artist, Title"; albums "Artist, Album") and library lists default to artist order (Conner: "so I can move by artist"). Recently added's directions are "Oldest added first" / "Most recently added first", oldest listed first.
- 4.1.0 Shift+F10 on a song (Conner): Play next, Favorite/Unfavorite, Add to playlist. All verified live against the real account (state put back).
  - Favorites are ratings of 1 on the CATALOGUE song (`GET /v1/me/ratings/songs?ids=` up to 300 per call ~0.4s; library ids answer nothing; `PUT`/`DELETE /v1/me/ratings/songs/{id}`). `RateAsync` runs after every fresh listing, so rows show first and ", favorited" is added quietly (`RenameAll` raises `Grew`). The menu item shows only once Apple has said (`IsFavorite` null hides it) and its words say what it will do.
  - Add to playlist: `canEdit` playlists only (Favorite Songs is not), cached by `LoadPlaylistsSoon` (entering Apple Music, every 5 min) and refreshed whenever Library\Playlists is listed; `POST /v1/me/library/playlists/{id}/tracks` (library-songs by library id, else songs by catalogue id); that playlist's listing is forgotten. Apple has no way to take a song back out through this API; test with a throwaway playlist and delete it with `DELETE /v1/me/library/playlists/{id}` from outside the page (from the page it fails CORS), and the listing lags the delete by seconds.
  - Play next: `_upNext` (newest first) and `_anchor` (the list song the list goes on from) in the player; page `requeue` = `queue.clearAfterCurrent()` + `playLater`. With nothing playing it plays now.
  - Playing on into a song Apple won't play (CONTENT_UNAVAILABLE) says so, skips it and carries on (`_autoGen`, at most 10 in a row); Enter on one still just says why.
- 4.1.1 (Conner: "adding a song to a playlist many times... it shouldn't let you. find more bugs"): Add to playlist reads the playlist from Apple first (`PlaylistSongsAsync`; empty playlist = 404 = empty) and refuses a song already there by any of its ids (`SongKeys`: catalogue and library ids), one add per playlist at a time (`PlaylistGates`), and trusts its own adds for a minute (`AddedTo`) because Apple's listing lags. Three code reviews (player; lists and menus; recent MainForm changes) then live checks found and fixed: Space right after Enter (`_wantPlaying` decides, page `holdPaused`), crash while paused (restarts paused at the place), Play next while loading (page `pendingRequeue`; play sends `_queuedId` read at send time) and Play next on the list's own next song (anchor moves past it), restart losing the list place (`StartKind`), non-play page errors no longer fail the song (logged), `Fail` stops the page, end of list clears the player (`EndOfList`) so Play next plays at once, volume while muted (`VolumeToStepFrom`) and lost on Quit (tray sets `_audio.VolumePercent`), superseded host starts and messages from an old page ignored, Search folder never cached (`Searches`), paging by raw page size (music videos), stable row paths per item id across refreshes, cursor kept when its row vanishes, account switch drops stale results (`_account`), per-batch favorites, "&" escaped in menus, Apple Music row and Apple panes hide refusing items, Audio menu hides effects while Apple plays, list named at once when a menu changed folder (`_menuOpen`/`_menuClosedAt`, 3s).
- 4.1.6 (Conner): the player keeps the rest of a chosen list as `_listQueue` (written out by `BuildListQueue` on Enter, from `AppleMusic.SongsShown`; null for stations, which go on through `NextSongAfter` until Up next is edited) plus `_history` for Previous. Shuffle shuffles the queue; Repeat all refills it (`Refill`); Repeat one queues nothing in MusicKit and restarts the song on "ended" (only if it made sound). Any queue change calls `Requeue` (page `requeue`, or `clearnext` when nothing is due). Up next is `UpNextForm` over `UpNext`/`MoveUpNext`/`RemoveUpNext`/`ClearUpNext`/`PlayUpNext` (Play next choices first; a song takes the kind of the place it lands in). `Settings.AppleMusicShuffle`/`AppleMusicRepeat` keep the modes; actions `ToggleShuffle`/`UpNext` are shortcut-only and shown in menus by MainForm (Audio menu S&huffle/Up ne&xt while Apple plays; Shift+F10 in Apple Music &Shuffle/&Repeat/&Up next). Go to artist/album (`GoToAsync`: library relationships for library songs, catalogue `include=albums,artists` otherwise, opened as a child of the song's folder), Add to library (`POST /v1/me/library?ids[songs]=`, 202), Remove from library (`DELETE /v1/me/library/songs/{i.id}`, catalogue songs via `?relate=library`), New playlist (`POST /v1/me/library/playlists` with tracks; adding a catalogue song to a playlist also puts it in the library). All endpoints checked live and the account put back.
- 5.5.0 Now playing (Conner: "I don't want to have to go deep into the station to find my now playing"): while the player has a song, the top folder starts with a row whose path IS the song's own path (so every Shift+F10 song item works on it), named by `NowPlayingName` ("Now playing" or "Paused", title by artist, from album, length, favorited). The top folder is rebuilt on every list (never served from memory, like Search); `AppleMusic.NowPlaying` is set by the tray from the player. MainForm's 1s `_nowPlayingTimer` swaps the row in quietly when the song or paused state changes; Enter on it is play/pause, never a restart; arriving from outside Apple Music lands on it. Shift+F10 song items gained Copy song lin&k (`SongLink`: music.apple.com/{storefront}/song/{catalogue id}; none for uploads) and C&opy lyrics. Tests in AppleMusicTests.NowPlayingRow.
- 5.6.0 resume (Conner): `Settings.AudioResumeOnStart` (Audio page) and `AppleMusicResumeOnStart` (Apple Music page), both off by default. Quit calls `RememberWhereWeWere` (tray): only something playing, never paused; a file as `AudioResumePath`/`AudioResumeSeconds` (stations at 0), an Apple song as `AppleMusicResumeSong` (`AppleMusic.ResumeLine`: catalogue id, title, artist, album, ms, second, tab separated; `FromResumeLine` registers it at `::applemusic\Resumed\<id>`). `ResumeAfterStart` plays it 1.5s after start (`AppleMusicPlayer.PlayFrom`, or `PlayAudioFile(path, startAt)` which seeks after opening; files waited for up to ~30s for the Drive letter or a share) unless something was chosen meanwhile. An update's `<exit>` or Ctrl+R sets `_quitToComeBack`, saved as `ResumeAfterRestart`, so playback carries on after them whatever the settings (Conner: "updates count too"). All four state values are `ThisPcOnly`.
- 6.1.1 (Conner: "the volume of apple music doesn't match the volume of the normal file audio... the volume range isn't the same. also skipping is slow"), all measured live: volume is the file player's dial exactly, 0 to `AudioPlayer.LoudestPercent` through `AudioPlayer.DirectGain` (squared to 100, plain above); it was percent / 100 capped at 100, so his 2 percent played 34 dB louder than a file. The page gets the multiplier: up to 1 is `music.volume` (which is the audio element's volume, linear), above 1 is a Web Audio GainNode (`wireBoost`: `createMediaElementSource` on the one audio element MusicKit keeps, made only the first time something above 1 is asked for, then `applySink` moves the context too). Proved with an AnalyserNode: protected audio does come through, half volume times gain 2 reads the same peak. The older line above saying volume is capped at 100 is history. Skips inside a song were already 11ms (the whole song is buffered in half a second); the slow thing was Next/Previous track, 0.55 to 1.4s, because every `play` built a new queue and MusicKit asked Apple for `webPlayback` again. `play` now steps (`skipToNextItem`/`skipToPreviousItem`) when the wanted song is the queue's neighbour and MusicKit is playing, checks it landed on it, puts the app's next after it, and falls back to the new queue otherwise: 0.3 to 0.4s. Preparing the next song early (`_playbackController.prepareToPlayNextItem`) bought nothing. To experiment in the page: start the app with `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9333 --remote-allow-origins=*` and send `Runtime.evaluate` over the WebSocket from `http://127.0.0.1:9333/json` (PowerShell's ClientWebSocket works; the page's top-level `music`, `audio()` and the rest are reachable).
- 6.2.0 (Conner: "I want all my existing audio affects to work. I want loading a playlist to be fast", then "pausing and playing holding doesn't work and skipping back and forth through the song lags too"), all measured live. Effects: the page has an AudioWorklet (`fxsrc` in `PlayerHtml`, class `Fx`) that is a port of the built-in player's own arithmetic, in its order: pitch (TimeStretch at 1/ratio then Resampler at ratio, so the length is unchanged), then gain above 1 and the limiter (`WasapiRenderer.ApplyGainAndMeasure`), then the equaliser (`Equaliser`), then fades. Change one of those C# files and the worklet has to change with it. The sound only goes through it once something needs it (`fxWanted`: volume above 1, or an effect on); until then the audio element plays straight out. It replaced 6.1.1's GainNode. `music.volume` still carries the part up to 1 (so an audio element not yet joined is never at full blast), and the worklet is told the whole gain and divides that part back out for the limiter's sums. Speed is the audio element's `playbackRate` with `preservesPitch` (MusicKit leaves it alone; a `ratechange` listener puts it back if not); pitch that moves the tempo at normal speed is `playbackRate` alone with `preservesPitch` off. The settings live in `AudioPlayer` (it holds them with nothing loaded) and `TrayApplicationContext.PushAppleEffects` hands them over through `AppleMusicPlayer.SetEffects` wherever one changes; the five dialogs and the speed keys are the built-in player's own. Silence reduction cannot cut (the page cannot look ahead): the worklet reports a silence past the minimum and the page plays at `SKIP_RATE` 4 (Chromium is silent above 4, and the end has to be heard) until sound returns. The context is `latencyHint: "interactive"` (10ms); 6.1.1's was `"playback"`, 80ms and more late on everything above 100 percent. Proved with a second `fx` node fed by an OscillatorNode into an AnalyserNode: +12 dB reads 3.981 times, an octave up reads 879.9 Hz from 440, the limiter at volume 3 puts a 0.01 tone at 0.908.
- 6.2.0, the rest. Held Play/Pause: MusicKit drops a `pause()` that arrives while a `play()` is still starting, and answers it at once, so the page ended playing with the app saying Paused. `settle()` in the page does pause and play one at a time, by the clock, ending on `holdPaused`; a `playbackStateDidChange` listener calls it again when a dropped pause shows. Skips: MusicKit's `seekToTime(t)` calls `sourceBuffer.remove(0, t)` and appends again from `t`, so after one of them (a song resumed part-way, a skip past the downloaded end) every skip backward was MusicKit's too, 325ms of silence each, where `audio.currentTime = t` inside the buffer has none. The page replaces `SourceBuffer.prototype.remove` so that removal removes nothing; a direct seek outside the buffer never recovers, so `inBuffer` still decides. Lists: `AppleMusicClient.ListStartAsync` gives the first page and a task for the whole; `AppleMusic.ListAsync(firstPageFirst: true)` (only the pane's own navigation asks for it) shows the first page, keeps the task in `Filling`, and `FillAsync` swaps the whole list in, raises `Grew` and calls `AppleMusicPlayer.ListGrew` so a queue made from the first page gets the rest. Every other caller gets the whole list, waiting on `Filling`. Before: 4,770 songs 4.0s, 2,245 songs 2.4s, library songs 4.9s, with the first page alone 0.4 to 0.7s. Held volume was measured the same on both players (2 to 227 against 0 to 210 percent in one second of holding, `music.volume` linear), so nothing was changed there. EXPLORERNATIVE_HOTKEYLOG now also logs every audio action with its repeat number and the volume.
- Nothing persists: the WebView2 profile is a throwaway `%TEMP%\ExplorerNative-AppleMusic\<guid>`, swept on start and deleted on exit, because the sign-in is injected afresh each run. The token lives only in `Settings.AppleMusicUserToken` (DPAPI, `ThisPcOnly`).
- Tests: `EXPLORERNATIVE_SELFTEST_ONLY=applemusic` (AppleMusicTests.cs; offline, via `ResetForTests`/`ConfigureForTests`/`SeedForTests`/`SetContainerForTests`). AppleMusicPlayer.cs is not in the suite (WebView2/WinForms); AppleMusic.cs and AppleMusicClient.cs are.
