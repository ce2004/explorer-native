2.0.0
Version 2.0 is the largest release of this program, with many improvements and new features.
Files sort the way File Explorer sorts them: Track 2 comes before Track 10, and names with accents sit with the other letters instead of at the end.
Typing a letter now finds names that start with that letter and an accent, so E finds Éclair. Pressing the same emoji again moves to the next name that starts with it.
Downloading into the folder you're looking at no longer makes the list reload over and over. The file's size updates where it is, and the cursor stays put.
When lots of files arrive in a folder at once, the list catches up every few seconds instead of reloading constantly.
Big folders that fill in while they load are much smoother to arrow through.
The Windows right-click menu opens much faster when many files are selected.
Bug fixed: pressing Escape to close the Windows right-click menu searched again or reloaded the folder. Now it just closes the menu.
While Explorer Native is hidden in the tray, it stops checking the folder and watching for changes, and catches up when you open it again.
Bug fixed: a USB drive could refuse to be safely removed while its folder was open in Explorer Native. Now Explorer Native lets go of it when Windows asks.
Reset to defaults keeps your web app pairing code, your Google Drive sync pairs, the folders you're in and where the window is. It also leaves Google Drive and the web app switched on, and never changes whether Explorer Native opens your folders or is on the right-click menu. The question now says what is kept.
Bug fixed: resetting preferences while the settings file couldn't be read could wipe the pairing code and sync pairs it promised to keep. Now it waits and says to try again, and it tells you if the reset couldn't be saved.
Bug fixed: copying or moving more than 2 gigabytes at once could say it failed after it had actually finished, and the rest of a move could be left undone. The same happened in the web app.
Bug fixed: while waiting for a file that is in use, the copy window garbled names with accents. Names now read correctly.
Bug fixed: moving a folder into a shortcut folder (a junction) that leads back inside it could copy the folder into itself over and over. It is now refused.
Moving files from a drive letter made with subst to the disk it stands for is now instant, instead of copying them.
Bug fixed: the count in the move window could go backwards when part of a move had to be copied instead of renamed.
Bug fixed: keeping both copies of a file could fail on USB sticks and network drives that don't support Windows' extra file data. The file now copies anyway.
Bug fixed: for names ending in a dot or a space, the Windows right-click menu could act on a different file with almost the same name. It is no longer offered for those names; the program's own commands work on them.
Typing a letter now also finds names written in wide letters, ligatures, and letters like Æ, Ø, Ł and ß, so typing AE finds Æble.
Bug fixed: a file name ending in a dot or a space could show another file's size and date while it was being written to.
Bug fixed: the list could reload, or say a folder changed, after you had already moved to another folder.
Bug fixed: cancelling an extract still said which files it had replaced or renamed. Now it just says it was cancelled.
Bug fixed: the progress window could say things like "3 of 0 items" before it knew how many there were. Now it says "3 items" until it knows.
A global shortcut message now says it needs Control, Alt or the Windows key, which is what Preferences already allowed.
Bug fixed: skipping in some damaged Ogg files could freeze playback and keep the file locked. Now playback stops cleanly.
Bug fixed: skipping right after resuming jumped to the wrong place.
Bug fixed: skipping past the end of some damaged or cut-off MP3 files could freeze the player. Now the track just ends.
Bug fixed: an Ogg file with the wrong extension, such as .mp3, wouldn't play. It plays now.
Stop is faster when a track is paused.
Very short sounds on repeat use much less of the processor.
Bug fixed: while music or an audiobook played in the web app, VoiceOver could stop talking and the page lagged. The page was updating the playback position every second. Now playback leaves VoiceOver alone, and the position only changes when you skip or seek. Press Time on Now Playing to hear where you are.
The web app looks and works just like the old iPhone app. Tabs along the bottom with icons for Files, Now Playing, Clipboard, Transfers and Settings. Each screen has its big title at the top, and in a folder the Back button names the folder it goes back to. Settings are in rounded groups with switches, folders have arrows, and each file has a More button for its actions. Now Playing has the title, the position slider, big skip and play buttons, then speed and the queue. Menus slide up from the bottom, and it follows your phone's light or dark mode. Each tab keeps its place when you switch away and back. The skip to content link is gone.
While something plays, a small player sits above the tabs with the title and a Play and Pause button. Tap the title to open Now Playing.
Bug fixed: in the web app, the drop-down lists in Settings and on Now Playing would not open with VoiceOver, so you couldn't change Sort by, When a name is taken, Skip back, Skip forward, Speed, Repeat or the Sleep timer. They open now.
New feature: Copy to iPhone, on the web app's Clipboard screen. Whatever is on the PC clipboard comes to your phone in one tap. Text goes straight onto the phone's clipboard and it says "Text copied to iPhone". Files and pictures download to the phone, show their progress in Transfers, and say "Saved to iPhone" when each one is done.
If the phone won't let the web app copy text, the text appears in a box with its own Copy button, so you can still get it.
Sending text or a file from the phone to the PC now says "Sent to the PC clipboard" when it arrives.
Bug fixed: opening a web page file from the PC in the web app could let that page act as you. Web pages, drawings saved as SVG, and scripts now download instead of opening, and nothing inside a file you open can run in the web app.
Bug fixed: empty files couldn't be uploaded from the web app or sent to the PC clipboard. They go like any other file now.
Bug fixed: if an upload from the web app stalled, it could stay stuck for over a minute. The PC now gives up on a stalled piece after 30 seconds, and the web app waits a little longer each time before trying again.
Bug fixed: uploading several files with the same name at once from the web app made most of them fail. Each one arrives now, with a number added when the name is taken.
Bug fixed: if the PC got an upload but its answer never reached the phone, trying again made a second copy. Now the PC knows it is the same upload and keeps one.
Bug fixed: pressing Stop on a small upload in the web app didn't stop it, and the file still arrived. Now it stops.
Bug fixed: moving something in the web app into the folder it was already in renamed it, or said it failed. Now nothing changes, and it says it is already there.
Bug fixed: in the web app, files and folders whose names end in a dot or a space couldn't be opened, downloaded, renamed, measured or played. They work now. Deleting one says why it can't go to the Recycle Bin, instead of saying it isn't there.
Bug fixed: a file open in another program on the PC showed as missing in the web app, or failed with an unclear error. Now it says the file is in use by another program.
Bug fixed: after Refresh or Delete in the web app, VoiceOver jumped to the folder's title. Refresh now stays where you were, and Delete lands on the next item.
Bug fixed: after sending to the PC clipboard failed, the web app still showed "Sent to the PC clipboard" from the time before.
Bug fixed: refreshing an empty folder while the PC couldn't be reached switched to the Can't reach the PC screen, while a folder with files in it only said so. Both now stay on the folder and say the PC can't be reached.
The delete question in the web app starts on Cancel, so a quick double tap doesn't delete anything.
VoiceOver now knows which tab each screen of the web app belongs to.
Explorer Native no longer wakes up every 10 seconds for the web app while nothing is being played or downloaded from Google Drive through it, which saves battery.
The Speech settings only list things Explorer Native actually says, in plain words. Each one is a checkbox: tick it to hear it, and press Preview to hear an example.
Bug fixed: Preferences and the Speech settings were slow to open, and lagged when you moved between pages or tabbed through them. They're instant now.
New installs start with no keyboard shortcuts. Set the ones you want in Preferences.
Updates never change your settings. Whatever you have set stays exactly as it is.
Bug fixed: typing a wrong option on the command line, such as --unistall, opened Explorer Native. Now it says the option isn't known.
Bug fixed: Check for updates said GitHub could not be reached when GitHub was only limiting checks for a while, and said you had the latest version when it couldn't find the list of releases. Now it says what actually happened.
Bug fixed: if the old copy took a long time to close during an update, the new version never started. Now it starts as soon as the old one has gone.
Bug fixed: the list of changes in the update window and the changelog could lose brackets, underscores and other characters from the release notes. They show as written now.
Bug fixed: pressing Alt+C on the Google Drive page in Preferences connected Google Drive instead of cancelling. Now Alt+C always means Cancel. Connect and Reconnect use Alt+N now, and Sign out of Google uses Alt+G, so Alt+O always means OK.
Bug fixed: on the Web app page in Preferences, Alt+O opened the web app in the browser and Alt+C copied the link, instead of OK and Cancel. Copy link is Alt+Y and Open in browser is Alt+B now.
Bug fixed: a keyboard shortcut could be just Shift and a letter, so Shift+P took away the capital P in every program. Shift on its own is now only allowed with a function key.
Bug fixed: pressing OK in Preferences could change settings you never touched. A read ahead size from an older version, a drive letter written in lower case, or the window shortcut could change, and Google Drive could move to another letter. Now OK only changes what you changed, and a setting the lists don't offer is shown as it is, marked custom.
Bug fixed: pressing OK in the Audio keyboard shortcuts window could blank a shortcut it didn't understand. Now only the shortcuts you set are saved.
Bug fixed: pressing OK in the Speech settings could forget choices made by a newer version of Explorer Native. They're kept now.
Bug fixed: if another program was holding the settings file when Explorer Native started, the web app's pairing code changed, and every browser had to enter the new one. Now the code stays the same.
Bug fixed: if the web app's port was busy when Explorer Native started, it used port 47810 and saved that over your choice. Now it uses 47810 just until the next start, and your port stays your setting.
Bug fixed: when you entered a new Google client ID and secret, they were saved even if OK then stopped on another problem and you pressed Cancel. Now nothing is saved until OK finishes.
The Audio page in Preferences says how many audio actions there are, instead of a number that was out of date.
Sort by in Preferences no longer offers Type, since there is no Type column.
Extracting a tar.gz into a new folder, and extracting any 7z, tar.xz, tar.bz2, tar.zst or rar, is about twice as fast.
Bug fixed: if one file in a 7z or similar archive had an unusual name, nothing extracted at all. Now everything else extracts and you're told which file was skipped.
Bug fixed: files in a 7z or similar archive with names Windows can't use, such as ones with a question mark or a colon, were quietly extracted under a different name. Now they're left out and you're told their names.
Bug fixed: if a 7z, tar.xz, tar.bz2 or tar.zst held two files with the same name, one was lost without a word. Now the first one is kept, as with zip and tar, and you're told.
Bug fixed: one shortcut in a tar.xz could stop its last file from extracting, and with Replace chosen, nothing was replaced. Now everything else extracts normally.
Bug fixed: a cut-off .gz file extracted as half a file and said it worked. Now you're told the file is damaged.
Bug fixed: a damaged or cut-off zip, tar, tar.gz or 7z gave a confusing error and often saved nothing. Now everything before the damage is saved, and you're told the archive is damaged and how many items were extracted.
Bug fixed: some very large files in tar archives, such as disk images, came out at the wrong size inside a folder called GNUSparseFile.0. They come out whole now.
Bug fixed: a 7z or tar.xz with a capital-letter name, such as BACKUP.7Z, couldn't be made.
Bug fixed: one file open in another program stopped a whole 7z or tar.xz from being made. Now the archive is made with everything else, and you're told which file was left out.
Bug fixed: 7z and tar.xz archives couldn't be made or extracted in very deeply nested folders.
Bug fixed: zips made by Windows and some other programs showed odd symbols in place of accented letters in file names. The names come out right now.
Bug fixed: password-protected zips gave a confusing error. Now you're told they need a password, which Explorer Native can't open.
Bug fixed: the progress for making a 7z, tar.xz, tar.bz2 or tar.zst could go past 100 percent.
Bug fixed: cancelling a zip extraction said files had been replaced when they hadn't been.
Bug fixed: compressing something that had been moved or deleted in the meantime said the archive was created. Now it says the item is no longer there.
Bug fixed: skipping a folder while extracting counted every file inside it as a separate skip.
Bug fixed: extracting the same files from a zip and from a tar gave different counts. They match now.
Bug fixed: if the web app's port was busy when Explorer Native started or reloaded its settings, your chosen port could be replaced with the default for good. Now the default is used until the next start, and your port stays your setting.
Bug fixed: a name with an ampersand in Preferences, such as a speaker called Tom&Cat, was read as TomCat and took over an Alt shortcut. It shows and reads as written now.
New: ExplorerNative --help, -h or /? lists the command-line options. A misspelt option with one dash or a slash, such as -install or /help, now says it isn't an option instead of opening the window.
Bug fixed: opening a lot of folders at once could leave some of them unopened. Every one opens now.
Bug fixed: pressing OK in Preferences could shorten a window title you set by hand that held unusual characters. The title only changes when you edit it.
Bug fixed: if every file you chose was in use, re-making an archive could replace the old archive with an empty one. Now the old one is kept and you're told why, and no empty archive is made.
Bug fixed: if Explorer Native closed unexpectedly while making a 7z, tar.xz, tar.bz2 or tar.zst, the compressing carried on by itself in the background. Now it stops when Explorer Native does.
Bug fixed: extracting into a folder that already had files in it could finish with the progress short of 100 percent, or at 0 percent when everything was skipped.
Bug fixed: an Ogg Vorbis file cut from part way through a longer recording could play nothing at all, and skipping in it landed in the wrong place.
Bug fixed: a .gz file with a few extra bytes after the end, which some downloads add, was refused as damaged. It extracts now, as it does with gzip.
Bug fixed: a very short sound on repeat always showed its position as 0. It shows where it is now.
Bug fixed: a hidden file on your PC could be treated as deleted by a two-way sync, sending the Drive copy to the trash. Hidden and system files, and files in folders that can't be read, are now left alone on both sides.
Bug fixed: when Google asked the Drive sync to slow down at one particular moment, the sync stopped and said it was offline. Now it waits and carries on.
Bug fixed: when Google's daily limit for your account was reached, a Drive sync pair said it could not sync. Now it waits, says so, and tries again every hour.
Bug fixed: when a file changed in both places and also had a second copy of the same name in Drive, the Drive sync could send a copy with changes your PC never had to the trash. Now that copy is kept.
Bug fixed: if Google Drive was briefly unavailable while a sync was keeping both copies of a changed file, the sync failed with "Could not find file". Now it waits and finishes.
Bug fixed: a file next to a folder with the same name in Google Drive failed to sync on every pass and left a part-downloaded file behind. Now it's left out, you're told once, and the part is removed.
Bug fixed: two Google Drive folders whose names differ only in capitals, such as Docs and docs, were synced as one, and the second was silently ignored. Now both are left out and you're told.
Bug fixed: a file whose name has an accent, copied from a Mac, could be synced as two files on each side. Now it's matched as one.
Bug fixed: copying or moving a file that another program had open showed Done in the web app even though nothing was copied, and replacing one said "1 replaced". Now it says the file is in use by another program, and a move leaves the original where it was.
Bug fixed: a web page somewhere else could talk to the web app's server on your PC by pointing its own address at your computer. The PC now only answers to its own names, and only takes changes from the web app's own page.
Bug fixed: there was no limit on guessing the web app's pairing code. After five wrong codes, each try now has to wait, starting at a second and going up to a minute, and the web app says how long. You, as the owner of the PC, are never held up.
If someone keeps entering a wrong pairing code, Explorer Native also says so out loud on the PC.
Bug fixed: the web app could be asked to open a network share path, which makes Windows offer your sign-in to that computer. Network paths are now refused; open shares through a mapped drive letter instead.
Bug fixed: uploading a small file with a very long name from the web app failed, and keeping both copies of a file whose name was nearly as long as Windows allows could fail too. Both work now.
Bug fixed: playing or replacing a file in the web app that another program had open said it couldn't be decoded, or that access was denied. Now it says the file is in use.
Bug fixed: a copy in the web app set to skip names that are taken said it failed when everything was already there. Now it finishes and says what it skipped.
Bug fixed: sending the same upload from the web app several times at once could make several copies. Now it arrives once.
Bug fixed: an upload or a file sent to the PC clipboard that stalled could hold on for over a minute and leave a hidden part-file in the folder. The PC now gives up after 30 seconds and removes it.
Bug fixed: stopping an upload in the web app while a piece of it was still arriving left that piece on the PC until the next start. It is removed straight away now.
Bug fixed: in the web app, pressing Select, or Copy and Move while selecting, sent VoiceOver back to the folder's title. Select now lands on the first item to tick, and Copy or Move on the Paste here button.
Bug fixed: the web app's mini player could make VoiceOver read the track's name again whenever the page updated. It only changes when the track does.
Bug fixed: two files or folders on your PC whose names look the same but have their accents written differently were synced to Drive as one, and only one of them went up. Now both are left out of the sync and you're told once.
Bug fixed: when a Drive folder's name had its accent written differently from the same folder on your PC, new files from Drive went into a second folder that looked the same. They now go into your PC's folder.
Bug fixed: compressing to .7z or .tar.xz when several files were open in another program could leave out files that were fine, without saying so. Now every readable file goes in, and every file left out is named.
Bug fixed: making a .tar of a file that was still being written could throw the whole archive away. Now the archive is kept and you're told the file changed while it was being read.
Bug fixed: while a Drive sync pair waited an hour for Google's daily limit, pausing the pair or closing Explorer Native didn't stop the wait. They do now, and Sync now tries again straight away.

1.0.7
The old iPhone app no longer works. Use the web app instead: open the link from Preferences, Web app in Safari and add it to your Home Screen.
New feature: Port, on the Web app page in Preferences. If another program needs port 47810, pick a different one. Explorer Native checks the port is free when you press OK and tells you if it isn't.
New feature: Copy link is always on the Web app page once there is a link. If the web app is off, it tells you to turn it on first.
The tray menu has a Web app item that takes you straight to the Web app page, where the link and the pairing code are.
The web app's clipboard shows what is on the PC clipboard right now, or says it is empty. It no longer keeps a history of past copies, on the PC or anywhere else.
If the PC can't be reached, the web app says so plainly and gives you a Retry button, instead of sitting there.
If your connection drops, uploads, copies and playback carry on by themselves when it comes back.
Bug fixed: if Tailscale stopped while you were using the web app, some screens waited for ever. Now they tell you what is wrong.
Bug fixed: if the port the web app used was taken by another program while the PC was off, the web app didn't start. Now it moves back to the usual port and tells you.
Small files upload from the web app in one go, so they finish faster.
The web app only listens on this PC itself now. It is reached through Tailscale and nothing else.

1.0.6
Pairing a folder with a Google Drive folder that already holds the same files adopts them instead of copying them again. Files of the same size are compared by checksum first, two at a time and gently, and each checksum is remembered so it is never worked out twice. The monitor says how far it has got.
A sync pair keeps what it remembers for as long as it exists. Changing its options keeps it; changing either of its folders starts again, still without copying anything that already matches.
When Google limits requests or has a server problem, the sync waits and tries again for as long as it takes, up to five minutes between tries, and never counts a file as failed for it. It says it is waiting and says when it carries on.
The Google Drive sync configurator is on the File menu while Google Drive is on, instead of in Preferences.
New: Explorer Connect as a web app. Open it in Safari on your iPhone or iPad over Tailscale and add it to your Home Screen; there is nothing else to install.
Preferences has a new Web app page. It finds Tailscale for you and says what is missing: Install Tailscale, Sign in to Tailscale, or Enable HTTPS in Tailscale. Then tick Turn on the web app and it shows the link to open.
The web app only works over your own Tailscale network. Nothing is reachable from the internet.
When you open it signed in to Tailscale as the owner of the PC, no pairing code is needed. Anybody else on your Tailscale network enters the pairing code once.
The web app browses every drive including Google Drive, opens, renames, deletes, copies and moves files, makes folders, uploads from the phone and saves files to the phone.
It plays music and audiobooks with a queue, skip back and forward, speed, repeat, shuffle and a sleep timer, with lock screen and headphone controls, and remembers where you were in each track.
It sends text and files to the PC clipboard and shows what is on it, with the clipboard history.
The web app has no equalizer.
Connecting Google Drive waits up to 30 minutes for you to finish signing in, instead of 3. Taking longer used to end on a browser page saying 127.0.0.1 refused to connect.
If the sign-in still takes too long, Explorer Native now says so: Google sign-in timed out, press Connect Google Drive again.

1.0.5
The drive list reads each drive as its letter, its name and how full it is, for example D, Google Drive, 1 terabyte of 5 terabytes used. Sizes are always in words: megabytes, gigabytes, terabytes.
New Google Drive monitor: Preferences, Google Drive, Configure Google Drive monitor. Choose folders on this PC to keep in step with folders in Google Drive.
Each monitored folder is two-way, upload only (a backup from the PC to Drive) or download only (Drive to the PC).
Deletes are only copied to the other side if you tick Also delete on the other side, and then they go to the Recycle Bin or the Drive trash.
A file changed in both places keeps both copies: the newer keeps the name, the other is renamed with the word conflict and the date.
Folders sync while Explorer Native is running and Google Drive is connected: a moment after anything changes on the PC, and every minute for changes in Drive. Sync now syncs straight away.
Each monitored folder can include or leave out its subfolders, skip file types you list, skip files over a size, choose what happens when a file changed in both places (keep both, this PC wins, or Google Drive wins), and choose how often Drive is checked, from every minute to only when you press Sync now.
Changes made while offline, or while Explorer Native was closed, are found and synced as soon as Google Drive is back, on either side.
Big transfers carry on where they stopped after the connection drops, instead of starting again. Downloads are checked against Google Drive's copy before they replace anything.
Before adding a folder, and before each file, the monitor checks there is room: it never fills the PC's disk past a margin, the larger of 2 gigabytes or 5 percent of the disk, and never asks for more than Google Drive has free. When a folder runs out of room it pauses, says so, and carries on by itself when there is space again.
A big sync says how much there is to do when it starts and again at a quarter, half and three quarters, and the monitor window shows how far each folder has got.
Deleting a folder that is part of a sync pair warns first and says what will happen on the other side. You can remove the sync and delete only here, delete anyway, or cancel.
If a monitored folder disappears on either side, because a USB drive was unplugged or the folder was deleted outside Explorer Native or trashed in Google Drive, the sync pauses and says so instead of deleting anything. It carries on by itself when the folder is back.
The Google Drive account button in Preferences says what it will do: Connect, Disconnect while Drive is working, or Reconnect when Google needs you to sign in again. Disconnect keeps you signed in.

1.0.4
Help, Changelog shows every version from GitHub. Tab moves between versions, the arrow keys read each one's changes, and Escape or Back closes it.
Changing the Google Drive letter in Preferences moves the drive straight away, instead of only after a restart. A folder open on the old letter follows it to the new one.
The drive list says each drive's name again, for example E: Backup, 12 gigabytes free.
Preferences can no longer be closed while it is checking the Google client ID and secret, which could sign you out or show an error after you had cancelled. Connect and OK no longer run two checks at once.
If Google refuses the client ID and secret, Preferences goes to the Google Drive page and puts you on the field to fix, from whichever page you pressed OK on.
Choose formats to play keeps formats you added yourself, and reads lists separated by commas or spaces.
A settings file that cannot be decrypted, such as one copied from another computer, no longer stops settings from ever saving again. A copy of it is kept and new settings are saved.
An update download that stalls gives up after five minutes instead of waiting for ever.
Release notes keep words like C# and track #3 intact.

1.0.3
Preferences is shorter. These are no longer settings, and always work this way: the folder name, full path, size and type are not announced when navigating or selecting; the list shows the Size and Modified columns and no Type column; volume moves one percent a press on the perceptual curve; holding a shortcut repeats it.
Playback speed is no longer in Preferences. Change it from the speed window.
Choose formats to play replaces the list of audio file extensions: a checklist of every format the player supports.
Read ahead is a list of sizes from 1 megabyte to 1 gigabyte, or off.
Google Drive has no on and off switch: it is on whenever you are signed in. It keeps up to 1 gigabyte of audio in memory, lets a file go after two idle minutes, and always starts downloading a file as soon as you copy it.
The Google Drive letter is a list of the letters not already in use.

Release notes are plain text, with no symbols for the screen reader to read out.
